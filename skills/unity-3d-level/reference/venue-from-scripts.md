# A venue built by script, in game coordinates

> Part of the `unity-3d-level` skill. For a level whose shape is fixed by the rules: a court, a
> pitch, a table, a track. The venue is generated by a Blender script that takes game
> coordinates, its collision is exported as data the game reads, and the playing surface is
> drawn in Unity from the same constants the rules use. Worked setting: three venues for a
> tennis game, rebuilt from a prior prototype's hand-made scenes.

A hand-modelled venue drifts. The prior prototype's court model had its lines 2.75 cm off the
rule positions and a flat net, and nothing noticed until the lines were checked against the
constants. A script that takes the same numbers the simulation takes cannot drift that way, and
rebuilding is one command instead of an afternoon in a GUI.

## 1. One coordinate system, end to end

Write every modelling function in **game coordinates** (metres; x right, y up, z along the court;
the net at z = 0). Blender is right-handed and Z-up, Unity left-handed and Y-up, so the move into
Blender is a mirror, and the FBX importer mirrors once more on the way out:

```python
# game (x, y, z) -> Blender, and back. One mirror each way.
def P(v): return (-v[0], -v[2], v[1])
def S(v): return (-v[0], v[2], -v[1])

bpy.ops.export_scene.fbx(filepath=path, use_selection=True, object_types={'MESH', 'EMPTY'},
                         axis_forward='-Z', axis_up='Y', apply_scale_options='FBX_SCALE_ALL',
                         bake_anim=False, mesh_smooth_type='FACE', path_mode='STRIP')
```

With that pair the imported model's local coordinates **equal** game coordinates: no root
rotation, no offset, no per-object fix-up. Prove it rather than reason about it:

- **An axis marker at an asymmetric point.** The script places a small cube `AxisMarker` at
  game (+3, 0.5, +10). An EditMode test loads the FBX and asserts the marker's bounds centre is
  there within 5 cm. A symmetric point such as (0, 0, 0) or (+3, 0, +3) cannot catch a swapped
  or mirrored axis.
- **Look from the player's seat in Blender.** With this map, looking along −Y from behind team 0
  shows game +x on the right, as in the game. Previews rendered from the game camera's pose then
  match screenshots.

`reference/modular-kit.md` §6 is the other route, for kit pieces modelled by hand: Blender's own
axes, `bake_space_transform`, and an audit that reads the pivot. Use one route per project.

## 2. Collision is data, exported from a collection

Collision lives in a `<Venue>_COLLISION` collection of simple objects named `COL_<name>`, each with
custom properties for its type (`box`, `soft`, `capsule`), a material and, for a capsule, a
radius. The exporter writes them to `<Venue>.colliders.json` in game coordinates:

- **Read each object's world matrix through `S`**, never the script's own input numbers. A proxy
  moved by hand in the `.blend` is then exported where it now is, and a re-export after a hand
  edit is a separate, cheaper command from a full rebuild.
- **Round to 0.1 mm** (`round(x, 4)`, and turn `-0.0` into `0.0`). The JSON then stays byte-stable
  across rebuilds, so a hash of the collision set (the game keeps one per venue, and the tests check the
  venues differ) changes only when a collider really moved.
- **Export the proxies inside the FBX too, as authoring-only objects.** A test compares each
  `COL_*` mesh's bounds in Unity with the box the JSON describes, within 1 cm; a capsule, modelled
  as a square prism, compares centres within 2 cm. Same count on both sides, or the test names
  the missing one. The prefab builder then deletes everything named `COL_*`, `AxisMarker` or
  `Tree_*` (placement markers), and a second test asserts none survived.

The tennis venues carried 37, 19 and 21 collision shapes, then 41, 23 and 25 once a tall fence was
added. Gameplay tests run against the exported data, not the meshes: every collider stays outside
the play area, the enclosure is closed on all four sides, a ball fired at the back wall comes
back, and a lob over the 1.15 m windscreen hits the tall fence instead of leaving the venue.

Where the game uses PhysX instead of its own simulation, the same collection becomes primitive
colliders on a `Collision` child: `reference/collision-proxies.md`.

## 3. Draw the rule surface from the rule constants

Lines, net and court surface are not part of the venue model. A Unity view builds them at runtime
from the same constants the simulation uses (line positions, line width, net height at the posts
and the centre), so a rule change moves the lines and the physics together and nothing can be
2.75 cm off. The venue model supplies everything around them: surround, fence, stands, trees,
water, sky.

## 4. Merge for the renderer, by material and zone

The `.blend` keeps one object per authored part, which is what a person edits. The exporter
merges a copy into one object per **(material, zone)**:

| Zone | What | Why |
|---|---|---|
| `Main` | Everything a match camera sees | Few objects, few draw calls |
| `Near0`, `Near1` | Scenery behind camera 0 and camera 1 | Each camera's culling mask drops its own: `unity-scene-optimisation` → `reference/culling-distances.md` |
| `Far` | Distant hills, water, sky dressing | No shadow casting |

LOD levels are a third key: `<venue>_<material>_LOD1_<zone>`. The FBX importer reacts to that
name by adding a `LODGroup`, which has to go: `unity-scene-optimisation` → `reference/lod.md`.

Colours come from one palette in the script (sRGB hex, smoothness, emission, casts shadows or
not), written to a JSON file next to the FBX. The Unity builder makes every material from that
JSON, so a colour changes in one place, and it logs an error for any material in the model that
the palette does not name.

## 5. One command per step

```bash
B=/path/to/Blender                                  # headless; --factory-startup ignores user add-ons
$B -b --factory-startup --python Tools/blender/venues/build_venues.py -- --repo . [--venue Garden] [--preview out/]
$B -b Art/venues/Garden.blend --python Tools/blender/venues/export_venue.py -- --repo .   # after a hand edit
unity -batchmode -quit -projectPath . -executeMethod Game.Editor.VenueAssetsBuilder.Build
```

The build writes the `.blend` (editable, before merging), the FBX, the collision JSON and the
palette; with `--preview` it renders a still from the match camera's pose and prints a triangle
report per zone and per LOD level. The Unity builder is idempotent: run twice, it produces no diff.
That last property is not free: URP rewrites materials it considers invalid, so the builder runs
URP's own validation itself (`unity-render-urp` → `reference/material-validation.md`).

## 6. A tall see-through fence

A fence above a low windscreen keeps high balls in play without hiding the far court. Model it as
one plane per side, UVs in metres, collision boxes per side (`fence_chain` type). In Unity it is a
double-sided transparent URP Lit material with a procedural diamond mesh texture; the material and
the mipmap rules that stop it shimmering are in `unity-render-urp` → `reference/material-validation.md` §3.

## Traps

| Symptom | Cause | Fix |
|---|---|---|
| The venue arrives mirrored or rotated 90° | Mixing the mirror map with `bake_space_transform`, or a hand-placed root rotation | One route; the asymmetric axis marker test |
| Collision JSON changes on every rebuild with nothing moved | Floating-point noise in the export | Round to 0.1 mm; normalise `-0.0` |
| A hand-moved collider snaps back after the next build | The exporter read the script's numbers, not the object | Export from world matrices; re-export after hand edits, rebuild only when the generator changed |
| Lines look right and the ball is called out on the line | The lines are part of a model, not the rules | Draw them from the rule constants |
| The low-tier trees vanish after a rebuild | The FBX importer added a `LODGroup` | Strip at prefab build; assert zero |
| Lanterns stop glowing after a rebuild | URP validation removed `_EMISSION` | `unity-render-urp` → `reference/material-validation.md` |
| A particle effect placed from a merged mesh's bounds sits over the court | Merging joined two separate areas (two halves of a lake) into one bounds | Place emitters from markers or from known zone limits; one system per area |
