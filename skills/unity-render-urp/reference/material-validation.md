# Materials built by script: run URP's validation yourself

> Part of the `unity-render-urp` skill. For any Editor script that creates or edits URP Lit,
> Simple Lit or Unlit materials: a venue builder, a palette importer, a prop pipeline. Worked
> setting: a tennis game whose venue materials are rebuilt from a palette file on every venue
> rebuild.

## 1. The symptom: a rebuild produces a diff, or a feature switches itself off

URP's material inspectors implement `ShaderGUI.ValidateMaterial`. Unity calls it when the material
is next inspected, reimported or upgraded, and it **rewrites keywords, blend factors, render
queue and enabled passes** to match the material's surface properties. A script that sets
`_Surface`, `_Blend` and friends by hand and stops there leaves a material that Unity will
"correct" later, so:

- every run of the builder is followed by a second, unasked-for diff in the `.mat` files, and
- a keyword the script enabled can disappear between the build and the next play.

Two cases from the tennis game's venue builder, URP 17.3:

| What the script did | What validation did later | Effect |
|---|---|---|
| `EnableKeyword("_EMISSION")`, emission colour set, `globalIlluminationFlags` left at `None` | Removed `_EMISSION`: it keeps the keyword only when the flags include `AnyEmissive` (`RealtimeEmissive` or `BakedEmissive`) | The lanterns stopped glowing |
| Transparent, `_Blend` = Alpha, `_SrcBlend` = `SrcAlpha` set by hand | `_SrcBlend` → `One` and `_ALPHAPREMULTIPLY_ON` on, because `_BlendModePreserveSpecular` is 1 by default (alpha is multiplied in the shader so specular survives); `DepthOnly` and `ShadowCaster` passes disabled because the surface is transparent; `m_DoubleSidedGI` followed the builder's `_Cull` = Off | Looked the same, but every rebuild rewrote the file |

## 2. The fix: call the same validation from the builder

```csharp
using UnityEditor;                                    // BaseShaderGUI lives here (URP editor assembly)
using UnityEditor.Rendering.Universal.ShaderGUI;      // LitGUI, SimpleLitGUI

static void ValidateLit(Material m) =>
    BaseShaderGUI.SetMaterialKeywords(m, LitGUI.SetMaterialKeywords);

// emissive material: the flag decides whether the keyword survives
m.SetColor("_EmissionColor", glow);
m.globalIlluminationFlags = MaterialGlobalIlluminationFlags.RealtimeEmissive;
m.EnableKeyword("_EMISSION");
ValidateLit(m);
EditorUtility.SetDirty(m);
```

After this the builder is idempotent: run it twice and `git status` shows nothing. That is the
acceptance test: **a second run of any asset builder changes no file.**

- Lit's own `ValidateMaterial` also calls `LitDetailGUI.SetMaterialKeywords`, which is `internal`.
  Materials with no detail maps lose nothing; a builder that sets detail maps has to set
  `_DETAIL_MULX2` / `_DETAIL_SCALED` itself.
- Simple Lit is `BaseShaderGUI.SetMaterialKeywords(m, SimpleLitGUI.SetMaterialKeywords)`; Unlit is
  `BaseShaderGUI.SetMaterialKeywords(m)`.
- The editor assembly needs a reference to `Unity.RenderPipelines.Universal.Editor`.
- `resources/Editor/UrpMaterialValidation.cs` does both jobs: `Validate(m)` for a builder, and
  `Audit(folder)`, a read-only report that validates a **copy** of each material and lists every
  one whose keywords, blend factors, queue, passes or GI flags would change. Run the audit before
  trusting any folder of script-made materials.

## 3. A see-through fence that does not shimmer

A tall chain-link fence that the far court is seen through, from both sides, in split screen:

| Decision | Value | Why |
|---|---|---|
| Surface | Transparent, alpha blend (validated, so premultiplied in the shader) | An alpha-test cutout of a sub-pixel wire pattern aliases into moiré and drops out entirely at distance; a blended texture averages to a faint tint |
| Faces | `_Cull` = Off | Each half of the split screen sees the fence from the other side |
| Shadows | Receive off (`_RECEIVE_SHADOWS_OFF`); casting is disabled by validation for transparent Lit | A wire mesh shadow is noise on the court |
| Texture | Procedural, 64 × 64, diamond lattice: alpha 0.95 on the wire, 0.05 in the hole | Generated by the builder, so it rebuilds with the venue |
| Import | Mipmaps on, trilinear, aniso 4, wrap Repeat, max size 64, `alphaIsTransparency` | The mip chain is what turns the far fence into an even haze instead of a crawling pattern |
| Tiling | UVs in metres from the modelling script; `_BaseMap` scale = 1 / cell size (0.22 m) | A stylised cell larger than a real 5 cm mesh, which reads at broadcast distance |
| Collision | Separate boxes per side | The mesh is one plane; the ball needs a solid |

The texture is two diagonal distance fields, so it tiles seamlessly at any size:

```csharp
float u = (x + 0.5f) / n, v = (y + 0.5f) / n;
float d1 = Mathf.Abs(Mathf.Repeat(u - v + 0.5f, 1f) - 0.5f);
float d2 = Mathf.Abs(Mathf.Repeat(u + v, 1f) - 0.5f);
float wire = Mathf.Clamp01(1.9f - Mathf.Min(d1, d2) * n * 0.7071f);   // ~2 px wire
byte a = (byte)(Mathf.Lerp(0.05f, 0.95f, wire) * 255);
```

## 4. Two project-level settings a runtime-built scene trips over

- **Fog variants are stripped when no scene in the build uses fog** (`unity-lighting` →
  `reference/environment.md`, Fog). A game that turns linear fog on from code when a venue loads,
  with a boot scene that has none, gets no fog in a player build. Fog Modes: Custom, keep Linear.
  From a builder:
  `m_FogStripping` = 1 and `m_FogKeepLinear` = true on
  `new SerializedObject(GraphicsSettings.GetGraphicsSettings())`.
- **A renderer whose `postProcessData` is null has no post-processing pass at all**
  (§1 step 3 of the router). A renderer asset created from script starts null: load
  `Packages/com.unity.render-pipelines.universal/Runtime/Data/PostProcessData.asset` and assign
  it, and log an error when that path does not resolve on the installed version.
- **A shader referenced only from code is stripped from the build.** A procedural sky material
  found by `Shader.Find` works in the Editor and is pink in the player; keep the material in a
  `Resources` folder or in Always Included Shaders.

## 5. Read it back

`git status` after a second builder run; the audit's `drift: []`; and a screenshot with the
emissive and transparent materials in frame (`unity-debug`). An emissive that is right in the
inspector and dark in the Game view is §1 again.
